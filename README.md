# A Per-Pixel Baseline Overstates the AlphaEarth Embedding's Advantage: A Context-Matched Test on Small-Parcel Coffee Boundary Delineation

[![DOI](https://zenodo.org/badge/DOI/10.5281/zenodo.24330614.svg)](https://doi.org/10.5281/zenodo.24330614)

Research code for the manuscript (in preparation for submission):

> **A Per-Pixel Baseline Overstates the AlphaEarth Embedding's Advantage: A Context-Matched Test on Small-Parcel Coffee Boundary Delineation**
> Abreu Filho, Leitão, Timbó Elmiro, Nero.

Ready-made embeddings are usually benchmarked against per-pixel features, although the
embedding itself integrates spatial context. Using 308,293 coffee parcels of at least one
pixel (median 1.0 ha) in Minas Gerais, Brazil (2017), identical Random Forest and linear
probes predict boundary probability from seasonal Sentinel-2 (E1), seasonal Sentinel-1+2
(E2), the AlphaEarth annual embedding (E3) and their fusion (E4), first per pixel and then
with the same four neighborhood features for every input (E1c–E4c); two fixed decoders (watershed
and region merging) extract parcel objects.

Because the neighborhood-feature control was added after the original test tiles had been
inspected, it was fixed in a written protocol
([`docs/protocol/confirmatory.md`](docs/protocol/confirmatory.md)) and confirmed on 48 new
tiles from 36 unused regions (protocol and tile list committed before any confirmatory imagery
was downloaded; no external registry). Per pixel, the embedding ranks boundary pixels better
(Boundary AP 0.579 vs 0.449). With identical neighborhood features the ranking reverses at exact one-pixel boundary localization: E1c 0.664
vs E3c 0.610 (Hodges–Lehmann E3c − E1c −0.052, 95% CI −0.063 to −0.043), the pre-specified
outcome "seasonal superior"; under the linear probe the difference is smaller (−0.026). With a one-pixel
tolerance E1c and E3c tie (post hoc, `code/14_posthoc_sensitivity.py`).
Adding the embedding to filtered seasonal inputs adds at most 0.02 AP. In this setting, a
per-pixel baseline overstated the embedding's advantage.

## Contents

- `code/` — pipeline steps `01`–`13` and shared modules (`probing.py`, `objects.py`,
  `stats.py`, `figstyle.py`, `paths.py`).
- `docs/protocol/` — confirmatory protocol (with frozen thresholds), ordered list of
  confirmatory candidate tiles (`confirm_tiles.csv`, `.geojson`), container `pip-freeze.txt`.
- `results/` — per-tile metrics, tests, thresholds and confirmatory summaries behind every
  number in the paper (`original_per_pixel/` E1–E4, `original/` and `confirm/` context-matched
  analyses, `confirm/posthoc/` post hoc checks).
- `Makefile` (`make figures`), `Dockerfile`, `compose.yaml`, `.env.example`.

## Reproducing

Every table and figure regenerates from public data with fixed seeds. See
[`REPRODUCING.md`](REPRODUCING.md) for the full walkthrough (Docker recommended; a Google
Earth Engine account is needed for the download steps).

```bash
cp .env.example .env          # set EE_PROJECT
docker compose build
docker compose run --rm pipeline earthengine authenticate
# then run code/01 ... code/12 in the order given in REPRODUCING.md, and `make figures`
```

Earth Engine collections can change: the Sentinel-2 composites differed between the July and
November 2026 downloads, with an effect on Boundary AP of at most 0.004 on the tiles checked.

## Data sources

- Reference parcels: CONAB crop mapping, distributed as
  [`br_conab`](https://source.coop/fiboa/data/br_conab) by the fiboa project.
- Sentinel-1 GRD, Sentinel-2 L1C (`S2_HARMONIZED`), and AlphaEarth Satellite Embedding V1,
  accessed through Google Earth Engine.

No raster data ships with this repository; everything under `data/` is regenerated by the
code. Because Earth Engine composites can change, `results/` holds the per-tile outputs that
the reported numbers come from.
